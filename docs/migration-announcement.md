## Release 正文

### DSH Desktop 退役：本仓库转为 DSH Pack 插件包

官方 **DeepSeek Harness 桌面客户端**已经发布，我们那个自制的临时桌面客户端就此退役。

从本版本起，这个仓库**不再产出任何 exe、安装包、托盘程序或自动更新链**。
我们这两年攒下的能力被重组为 **DSH Pack** —— 一组装进官方客户端的插件包，
通过官方自己的插件机制分发：29 个插件，由一个聚合元包 `@dsh-pack/all` 一次装齐。

### 你会失去什么

诚实列出来，避免装好后才发现：

- 托盘常驻、关窗最小化到托盘、一键重启
- 会话完成的**系统级**通知（降级为页内提醒）
- `harness-pet` 的原生悬浮窗（页内宠物仍在）
- WSL 后端（把内核跑在 WSL 发行版里）
- 自定义应用图标
- 自制壳那条 36px 玻璃标题栏与 ⋯ 菜单（官方用自己的原生窗口装饰）

### 你会得到什么

- 官方客户端的原生体验、签名、强制更新通道，不用再等我们跟进内核破坏性变更
- 余额坞、文件一键还原、剪贴板图片落盘这些原本由壳层代做的能力，
  现在由插件自己的宿主半边完成 —— **功能保留，实现搬家**
- 一个真实空缺被补上：官方客户端**完全没有**账户余额/费用显示

### 迁移三步

1. 安装官方 DeepSeek Harness 客户端。
2. 打开它 —— 你的会话、凭据、设置都在 `~/.dsh` 下，**官方客户端读同一个目录，不会丢**。
3. 在客户端内 **设置 → 插件**，装聚合元包：

   | 包 | 内容 |
   | --- | --- |
   | `@dsh-pack/all` | 29 个插件，一次装齐（首次安装会要放行一次构建脚本，见下） |

   只此一个元包，**没有可叠加的分层**。想要一个小集合，就按用途在插件页里单独装某个
   插件包（每个成员都能独立安装）——但**别和 `all` 混装**：内核组合补丁层时对 `insert`
   不按 id 去重，`all` 里已有的成员再单独装一次就是把它装配两次，真机报
   `webserver: duplicate exact route "…"`（细节见 `docs/recovery.md`）。

### 两个会让人觉得「坏了」的点

1. **启用/停用插件要重启整个应用，不是刷新页面。**
   官方宿主只在进程启动时抓一次页内注入清单，之后是快照；按 F5 看不到效果。
2. **`@dsh-pack/all` 首次安装会失败一次**，报 `Ignored build scripts: @photostructure/sqlite`
   （这个原生依赖由 `all` 里的 `graph-memory` 带进来）。
   在「设置 → 插件」点 **「Allow these scripts and retry」**。
   预编译二进制其实都在包内，这道点击只是让安装器闭嘴，不需要你装 C++ 工具链。

### 命令行装不了

`dsh plugin --profile desktop …` 会被官方 CLI 硬拦
（`profile "desktop" is managed exclusively by the Electron application`）。
那个 profile 归桌面应用独占。安装只有上面两条通道：应用内「设置 → 插件」，
或让应用里的 agent 用 `install_bundle` 工具装。

### 旧客户端怎么办

它不会坏，但**不会再更新**。`%LOCALAPPDATA%\Programs\DSH Desktop` 请自行卸载。
迁移细节与出问题后的恢复步骤见仓库 `docs/recovery.md`。

## 置顶 issue 正文

**标题：** DSH Desktop 已退役 —— 本仓库改为 DSH Pack 插件包（装进官方客户端）

正文沿用上面 Release 的「你会失去什么 / 你会得到什么 / 迁移三步 / 两个会让人觉得坏了的点 /
命令行装不了 / 旧客户端怎么办」六段，另外加：

- **不要在新仓库上提客户端层面的 issue**（托盘、常驻、原生通知、自定义图标、WSL）。
  这些是原生窗口管理能力，插件形态下做不到，已明确决定**不留任何原生伴侣进程**。
  issue 只收插件包范围内的东西。
- 我们从自制壳迁到纯插件包时，放弃了全部内核补丁层。其中两簇是**真实的上游缺陷**，
  已整理成可复现的正文放在 `docs/upstream/`：
  会话日志读路径 fail-closed 导致历史不可读（一台机器实测 54 个会话里 19 个打不开），
  以及 `dsh-llm-pi-ai` 四处 provider 错误误分类。
  如果你就是被这些坑打到过的人，请到上游仓库给那两条 issue 加持。
